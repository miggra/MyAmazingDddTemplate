# DDD Шаблон .NET Проекта

Этот шаблон предоставляет структурированную основу для создания .NET приложений, следуя принципам предметно-ориентированного проектирования (Domain-Driven Design, DDD).

## 🚀 Установка и использование шаблона

### Установка шаблона

1. Склонируйте репозиторий с шаблоном
2. Перейдите в корень локальной папки репозитория шаблона
2. Установите шаблон локально с помощью команды:
```powershell
dotnet new install .\
```
Теперь шаблон можно использовать для создания проектов используя команду:
```dotnet
dotnet new ddd-webapi -n ИмяВашегоПроекта
```


### Создание нового проекта

После установки шаблона вы можете создать новый проект одним из следующих способов:

1. Используя короткое имя шаблона:
```powershell
dotnet new ddd-webapi -n ИмяВашегоПроекта
```

2. Или используя полное имя:
```powershell
dotnet new MyAmazingDddTemplate -n ИмяВашегоПроекта
```

Параметр `-n` задает имя для вашего нового проекта. Все вхождения "MyAmazingDddTemplate" в коде будут заменены на указанное вами имя.

```
    └── ArchitectureTests/   # Архитектурные тесты
```

## 📝 Основные концепции DDD в шаблоне

### Доменный слой (Domain)
- Содержит бизнес-логику и правила
- Независим от внешних зависимостей
- Включает сущности, агрегаты, объекты-значения и доменные события

### Слой приложения (Application)
- Оркестрирует взаимодействие между доменными объектами
- Определяет интерфейсы для внешних сервисов
- Содержит DTOs и маппинги

### Инфраструктурный слой (Infrastructure)
- Реализует интерфейсы, определенные в слое приложения
- Содержит реализации для работы с базой данных
- Включает интеграции с внешними сервисами

### Web API слой
- Предоставляет HTTP endpoints
- Обрабатывает запросы и ответы
- Содержит middleware и фильтры

## 🛠 Лучшие практики
1. **Сохраняйте доменный слой чистым**
   - Без зависимостей от внешних фреймворков
   - Бизнес-логика должна быть независима от фреймворков
   - Используйте интерфейсы для определения внешних зависимостей
2. **Разумно используйте агрегаты**
   - Проектируйте агрегаты для поддержания границ согласованности
   - Держите агрегаты небольшими и сфокусированными
   - Доступ к дочерним сущностям только через корень агрегата
3. **Следуйте паттернам DDD**
   - Используйте фабрики для создания сложных объектов
   - Реализуйте репозитории для поулчения сущностей
   - Применяйте паттерн спецификации для сложных запросов
4. **Поддерживайте разделение слоев**
   - Доменный слой не должен зависеть от других слоев
   - Слой приложения зависит от доменного слоя
   - Инфраструктура реализует интерфейсы, определенные в слое приложения
   - Слой представления зависит от слоя приложения
5. **Используйте CQRS подход для разделения операций чтения и записи**
   - Используйте Query для чтения данных
   - Убедитесь что Query не вносят изменений в данные
   - Используйте Command для операций изменения данных

## 🔧 Конфигурация

1. Настройте строки подключения в `appsettings.json`
2. Настройте dependency injection в `Program.cs`
3. Сконфигурируйте middleware в порядке, необходимом для вашего приложения
